The manifest.toml file defines **runtime defaults** for images built with Fledge. This file is separate from fledge.toml (which defines build-time configuration) and represents the template for what the image provides when VMs are created from it.

## Overview

manifest.toml is:
- A TOML source file that lives alongside fledge.toml in your project
- Read by `fledge build` and merged with build metadata to produce manifest.json
- The source of truth for runtime defaults (CPU, memory, environment, networking)
- Overridable at VM creation time via CLI flags

The resulting manifest.json is what gets installed into the image registry and used by volantd to create VMs.

## File Location

```
my-project/
├── fledge.toml      # Build-time configuration
├── manifest.toml    # Runtime defaults (this file)
├── Dockerfile       # Optional
└── dist/
    ├── manifest.json    # Generated by fledge build
    └── rootfs.img      # or plugin.cpio.gz
```

## Required Fields

### Top-Level Metadata

```toml
schema_version = "1.0"    # Required: manifest schema version
name = "myapp"            # Required: image name
version = "1.0.0"         # Required: semantic version
runtime = "myapp"         # Optional: defaults to name if omitted
```

- **schema_version**: Must be "1.0"
- **name**: Unique identifier for this image
- **version**: Semantic version string
- **runtime**: Runtime identifier (defaults to name)

### Resources

```toml
[resources]
cpu_cores = 2       # Required: default CPU cores (must be > 0)
memory_mb = 1024    # Required: default memory in MB (must be > 0)
```

These are the **default** resources for VMs created from this image. Can be overridden with `--cpu` and `--memory` flags.

### Workload

```toml
[workload]
entrypoint = "/usr/bin/myapp"    # Required: command to execute
args = ["--port", "8080"]         # Optional: arguments to entrypoint
```

- **entrypoint**: The main command/binary to run (required)
- **args**: Array of arguments passed to entrypoint (optional)

## Optional Sections

### Environment Variables

```toml
[workload.env]
PORT = "8080"
LOG_LEVEL = "info"
DATABASE_URL = "postgres://localhost/myapp"
CACHE_ENABLED = "true"
```

All values must be strings. These are merged with VM-level `--env` flags (VM flags take precedence on conflicts).

### Network Configuration

```toml
[network]
mode = "bridged"    # "bridged" (default), "vsock", or "dhcp"

# Port exposures
[[network.expose]]
port = 8080
protocol = "tcp"    # "tcp" or "udp", defaults to "tcp"
host_port = 8080    # Optional: map to different host port

[[network.expose]]
port = 443
protocol = "tcp"
```

Network modes:
- **bridged**: VM gets static IP from managed subnet (default)
- **vsock**: No Ethernet, vsock-only communication
- **dhcp**: Tap device provided, VM runs DHCP client

Port exposures:
- Defines which ports the workload listens on
- Can be completely replaced with `--port` flags at VM creation

### Actions

Define custom API endpoints exposed by the guest agent:

```toml
[actions]

[actions.restart]
description = "Restart the application"
method = "POST"
path = "/api/restart"
timeout_ms = 30000

[actions.reload_config]
description = "Reload configuration without restart"
method = "POST"
path = "/api/reload"
timeout_ms = 5000
```

These become available at `/vms/{name}/actions/{image}/{action}` on the volantd API.

### Cloud-Init

```toml
[cloud_init]
datasource = "nocloud"    # Currently only "nocloud" supported
seed_mode = "vfat"        # "vfat" (default) or "iso9660"

[cloud_init.user_data]
content = '''
#cloud-config
users:
  - name: admin
    ssh_authorized_keys:
      - ssh-rsa AAAA...
packages:
  - curl
  - htop
'''

[cloud_init.meta_data]
content = '''
instance-id: my-instance
local-hostname: myapp
'''

[cloud_init.network_config]
inline = false
path = "./network-config.yaml"  # Can reference external file
```

Cloud-init configuration for VM initialization. Can be overridden at VM creation time.

### Devices (PCI Passthrough)

```toml
[devices]
pci_passthrough = ["0000:01:00.0", "0000:01:00.1"]
allowlist = ["10de:*", "8086:1234"]  # Vendor:Device patterns
```

- **pci_passthrough**: Array of PCI addresses to pass through
- **allowlist**: Security allowlist of vendor:device patterns (vendor:* allowed)

### Labels

```toml
[labels]
environment = "production"
team = "platform"
cost_center = "engineering"
version_tag = "v1.2.3"
```

Arbitrary key-value metadata for organizing and querying images.

## Complete Example

```toml
# manifest.toml - Complete example

schema_version = "1.0"
name = "web-api"
version = "1.2.3"
runtime = "web-api"

[resources]
cpu_cores = 2
memory_mb = 1024

[workload]
entrypoint = "/usr/bin/api-server"
args = ["--config", "/etc/api/config.toml"]

[workload.env]
PORT = "8080"
LOG_LEVEL = "info"
LOG_FORMAT = "json"
METRICS_ENABLED = "true"
METRICS_PORT = "9090"
DATABASE_URL = "postgres://db.internal/api"
CACHE_URL = "redis://cache.internal:6379"
JWT_SECRET_PATH = "/run/secrets/jwt"

[network]
mode = "bridged"

[[network.expose]]
port = 8080
protocol = "tcp"

[[network.expose]]
port = 9090
protocol = "tcp"
host_port = 9090

[actions]

[actions.health]
description = "Check application health"
method = "GET"
path = "/health"
timeout_ms = 5000

[actions.reload]
description = "Reload configuration"
method = "POST"
path = "/admin/reload"
timeout_ms = 10000

[cloud_init]
datasource = "nocloud"

[cloud_init.user_data]
content = '''
#cloud-config
packages:
  - curl
  - jq
write_files:
  - path: /etc/systemd/resolved.conf.d/dns.conf
    content: |
      [Resolve]
      DNS=8.8.8.8 8.8.4.4
'''

[labels]
environment = "production"
team = "backend"
service = "web-api"
```

## Build Workflow

1. Create fledge.toml (build config) and manifest.toml (runtime defaults)
2. Run `fledge build`
3. Fledge reads both files
4. Generates manifest.json by merging:
   - manifest.toml (runtime defaults)
   - Build metadata (image name, boot media URLs, checksums)
   - Agent configuration
5. Outputs manifest.json + boot media to dist/

## Runtime Override Hierarchy

When creating VMs, configuration is merged:

```
VM Creation Flags  >  manifest.toml defaults  >  System defaults
```

Example:

```toml
# manifest.toml
[resources]
cpu_cores = 2
memory_mb = 1024

[workload.env]
LOG_LEVEL = "info"
PORT = "8080"
```

```bash
# Override CPU and add environment variable
volar vms create prod --plugin web-api \
  --cpu 4 \
  --env LOG_LEVEL=debug \
  --env DATABASE_URL=prod.db.internal
```

Result:
- CPU: 4 (overridden)
- Memory: 1024 (from manifest)
- LOG_LEVEL: "debug" (overridden)
- PORT: "8080" (from manifest)
- DATABASE_URL: "prod.db.internal" (added)

## Validation

Fledge validates manifest.toml during build:

**Required checks:**
- schema_version must be "1.0"
- name must not be empty
- version must not be empty
- resources.cpu_cores must be > 0
- resources.memory_mb must be > 0
- workload.entrypoint must not be empty

**Optional checks:**
- network.mode must be "bridged", "vsock", or "dhcp"
- network.expose[].protocol must be "tcp" or "udp"
- PCI addresses must match format XXXX:XX:XX.X
- Labels keys and values must be strings

## Differences from manifest.json

manifest.toml is the **source** file you write.
manifest.json is the **generated** file that includes build metadata.

manifest.json adds:
- `initramfs` or `rootfs` section with URLs and checksums
- `image` and `image_digest` (for OCI sources)
- Normalized and validated fields
- Agent configuration details

You never edit manifest.json directly - it's always generated by `fledge build`.
